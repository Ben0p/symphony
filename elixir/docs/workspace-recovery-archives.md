# Workspace recovery archives

The managed work-package cleanup adapter preserves local work before removal. The
orchestrator first validates terminal state, exact accepted head, reconciled
ownership and released leases. It persists cleanup intent and archive evidence
before removing the workspace. Archive preparation also rejects an obsolete
generation or an entry path different from the recorded workspace.

Version 2 archives contain:

- `repository.bundle`: the existing Git history/ref recovery bundle, verified by
  cloning it and checking the accepted head;
- `workspace/`: exact regular file bytes, including dirty, untracked and ignored
  files, plus empty directories; root Git administration metadata is excluded;
- `manifest.json`: Git status, staged/unstaged binary diffs, unmerged index
  records, open PR candidates, exact issue/generation/repository/branch/head, and
  the inventory bound to the durable SHA-256 evidence reference.

Every inventory entry has a relative path and type. Regular files include byte
size, SHA-256 and source mode. Directories include source mode. Links include the
exact target string, its byte size and SHA-256. A Windows junction is recorded as
`symlink`, matching the runtime's `lstat` representation. No link target is read
as archive content, including nested links leading to shared or canonical data.
No link is physically created inside a version 2 archive.

Source modes remain manifest metadata so verification can run on filesystems
with different permission semantics. Physical verification checks file bytes and
directory identity, rejects physical links and unexpected entries, and verifies
the bundle. The manifest and all its metadata must still match the persisted
evidence reference. Relative traversal, conflicting paths, unsupported special
files and path names that cannot be represented safely fail closed.

## Recovery

Recover into a new disposable location, keeping the archive unchanged. Verify
the manifest against the original evidence reference and verify the bundle
before importing it. A checkout from the bundle recovers committed content;
`workspace/` preserves the final working bytes. The staged diff and unmerged
index records are separate Git state evidence, not a claim that a plain checkout
reconstructs the index or dirty work automatically.

For ordinary staged work, initialize a recovery index from the accepted head,
apply the recorded staged binary diff to that index, and restore the recorded
working snapshot, including recorded absences. Confirm Git status and diffs
against the manifest before using the recovered work. Handle conflicted index
records explicitly; never discard the original archive after a partial restore.

Link reconstruction is a separate, explicit operator action. Read each verified
link entry and inspect its original target before creating a corresponding link
under the new recovery root. Relative targets remain relative to their link's
parent; external targets are dependencies, not archived bytes. On Windows a
directory junction can be recreated without symlink elevation. Do not silently
remap absolute targets or let restoration write through a recreated link. The
tests reconstruct synthetic links and check that shared/canonical markers remain
exact; archive verification itself never performs that action.

## Retry and compatibility

The single stopped-writer invariant is required. Before/after inventories and a
final Git/head/PR comparison catch persistent source changes during copying or
bundle creation. They are not filesystem isolation against hostile concurrent
mutation. A retained source change prevents archive publication and workspace
removal.

An interrupted `.staging` directory can be rebuilt while the source still exists.
Staging removal errors propagate; the pinned runtime removes links without
traversing their targets. A final archive missing its manifest is preserved and
reported as `cleanup_archive_incomplete`. Existing final archives are verified
and reused only when their source state and original evidence still match.

Version 1 archives keep their previous physical-link inventory format and hash
calculation. They are read and reused without rewriting them as version 2. The
checked-in compatibility fixture was generated by the accepted legacy module at
`0610c854f716ae258656f6970603bdc6b13a0622`, and retains the original manifest bytes.

These are source and synthetic recovery guarantees. Runtime installation,
provider scope release and automatic successor admission require their own
managed execution acceptance.
